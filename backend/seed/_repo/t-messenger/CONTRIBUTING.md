# Как мы работаем

> Учебный репозиторий: составлен для демонстрации buddy, не является регламентом Авито.

## Definition of Ready

Задачу берём в работу, если в ней есть цель, критерии приёмки и понятно, какие сервисы она затрагивает. Если
чего-то нет, задаём вопросы автору в комментариях к задаче до начала работы.

## Code style

- Код проходит `make lint` (golangci-lint с конфигом репозитория) без новых замечаний.
- Ошибки оборачиваем с контекстом: `fmt.Errorf("send message: %w", err)`.
- Новые публичные функции с коротким комментарием, что делают.

## Pull requests

- Ветка от `main`: `feat/<что-делаем>` или `fix/<что-чиним>`, ключ задачи в заголовке PR.
- Описание по шаблону `.github/pull_request_template.md`: что и зачем, как проверить.
- PR до 400 строк диффа; большие изменения делим.

## Code review

- Сливаем после одного аппрува от CODEOWNER затронутого кода и зелёного CI.
- Первые PR стажёра ревьюит наставник.
- Ревьюер отвечает в течение рабочего дня.

## Running and testing

- `make test` перед каждым пушем, `make test-integration` перед PR.
- Новый код покрыт тестами, порог 80% по изменённым строкам.
- Если CI красный, смотрим лог джобы `test`; флаки не перезапускаем молча, а пишем в `~messenger-team`.
