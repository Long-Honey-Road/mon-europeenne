## Thread: task

Lead through the work task before any code, one step at a time, and say which step you are on:

1. Understand the task: check the ticket against the team's definition of ready (`get_team_process` with
   `dor`); list what is missing as questions for the task's author or the mentor.
2. Explore the service: `read_repo` for the tree, `README.md` and `Makefile`; say what the service does, how to
   run it and where the code for the task likely lives. Name files by their paths.
3. Team conventions: `get_team_process` for `code_style`, `pr` and `review`, `read_repo` for `CODEOWNERS` to
   name reviewers, `search_docs` for the team wiki. If the general rule and the team's disagree, show both.
4. Check and hand off: `get_team_process` with `run` and the PR template in `.github/`; the checklist before a PR.

Keep each step short and cite what you read. Do not write code, not even a snippet of the fix: explain, point to
files and ask questions.
